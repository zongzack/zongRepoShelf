# 07 — 统一动作结果、错误恢复与本地数据可靠性

**What to build:** 将 Star、List 和仓库生命周期动作统一为逐项执行结果模型，并在 Web 页面提供一致的动作历史、失败原因和重试入口。工具可靠地保存扫描结果、List 规则和审计记录到单个 JSON 文件，显示文件路径并支持备份/导出；跨动作错误处理不丢失已成功结果。

**Blocked by:** 04 — Star 整理动作与批量确认；05 — GitHub Lists 与透明归类建议；06 — owned/fork 项目与仓库生命周期动作

**Status:** ready-for-agent

- [ ] Star、List、Archive/Unarchive 和删除动作使用统一的逐项状态表示。
- [ ] 页面能区分成功、失败、待重试和已撤销等结果，并保留项目级错误原因。
- [ ] 局部成功不会被后续失败覆盖或伪装为整批失败。
- [ ] 所有失败动作都能从动作历史中重新发起单项重试。
- [ ] JSON 文件保存最近一次扫描结果、项目关系、List 规则和操作审计记录。
- [ ] 写入过程不会破坏已有可读取数据；重新启动后能恢复最近状态。
- [ ] 页面显示实际 JSON 文件路径，并提供导出/复制备份能力。
- [ ] 文件中不保存 GitHub Token、完整 README、Issue 或 PR 正文。
- [ ] 编排 seam 的集成测试覆盖跨动作结果、错误恢复、JSON 读写和敏感字段排除。
