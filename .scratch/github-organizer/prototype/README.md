# GitHub 整理 Web UI 原型

这是一次性 UI/UX 探索原型，不连接 GitHub、不写入本地数据，也不会执行真实的 Star、List、Archive 或删除操作。

## 运行

在仓库根目录执行：

```bash
python3 -m http.server 4173 --directory .scratch/github-organizer/prototype
```

然后打开：<http://127.0.0.1:4173/?variant=A>

也可以直接双击 `index.html` 打开。底部浮动切换条或键盘左右方向键可以切换方案；URL 参数可用 `A`、`B`、`C`。

## 三个方案

- `A`：审阅队列。左侧工作区导航，主区域是带证据和建议的项目卡片，适合逐条判断。
- `B`：批量表格。高密度表格配右侧详情，适合比较时间戳、筛选和按动作分组批量确认。
- `C`：Lists 工作台。以 GitHub Lists 为主导航，使用双列看板探索待决定与已归类项目。

## 要观察的问题

1. 你能否在 5 秒内理解“为什么这个项目需要处理”？
2. 哪种方案最容易完成“筛选 → 多选 → 按动作分组确认”？
3. 你更常从“健康信号”开始，还是从“GitHub List”开始？
4. 删除仓库的危险护栏是否足够醒目但不干扰普通整理？
